# 000 定位与原则

## 要解决的问题

用 DSH 的人一旦同时开多个 Session，挂上 goal 自动续轮、schedule 定时任务、子代理或 Agent Team，就会遇到同一个问题：**谁在等我？** 审批、提问、计划审批卡在一个没有打开的 Session 里，可能空等几个小时；goal 已经 blocked，没人知道；夜里定时任务跑完了，结果没人看。

文章把这叫作**注意力义务**：系统不可避免地需要人的注意力时，这个需求应当被追踪、被记录，并作为系统设计的第一约束。原型的面板第一个要回答的问题也是"现在有什么需要我？"。

## 和原生侧栏的关系：不做复刻

DSH Web 的侧栏已经在每个 Session 行上标出 `pendingInteraction`（等待审批、计划待审、等待回答）和"已完成未查看"（见 `dsh-client-ui-workspace`、`dsh-client-ui-session` 的 `uiSession.sessionStatus`）。只把这些状态再列一遍，就是玩具。本插件**复用同一份状态**，确保两边不会互相矛盾，然后补上侧栏做不到的部分：

| 能力 | 原生侧栏 | 注意力收件箱 |
|---|---|---|
| 范围 | 每个 Workspace 只展开有限行（上限 50 行），折叠的 Workspace 看不到 | 所有 Workspace 汇成一个队列，按紧急程度和等待时长排序 |
| 处理 | 必须先打开那个 Session | 审批、回答、计划审批直接在收件箱完成 |
| 义务种类 | 只有正在进行的交互，以及本地记录的"完成未读" | 还包括 goal 受阻、失败的轮次、凭据失效、自主运行产出待验收 |
| 持久性 | "完成未读"只存在当前浏览器本地 | 存在 Host 上，重启、换设备后仍然在 |
| 降噪 | 无 | 漏斗规则、稍后提醒、静音，并显示"今日已替你挡掉 N 条" |
| 度量 | 无 | 注意力账本：响应时长、噪音率 |
| 扩展 | 无 | 后续插件可以提交义务、注册主体类型和投递通道 |

## 原则

原型的 [000 Philosophy](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/000-philosophy.md) 和文章的六条原则，落到这个插件上就是下面七条硬约束。之后每一项设计都要能对应到其中一条，对应不上的就删掉。

### P1 省下的注意力必须多于消耗的注意力

收件箱里每一个条目、每一个数字、每一句说明都在消耗注意力。一个数字只有在会改变你下一步动作的时候才出现。账本（见 [001](001-domain.md)）让这条原则可以验证。

### P2 完整且诚实

- **完整**：只要有一件事在等你，它就必须出现在收件箱里。漏掉一件，用户就会回去逐个翻 Session，插件的价值归零。所以义务**由事实推导**，不靠 agent 自觉上报。
- **诚实**：徽标上的数字等于列表长度；已经不可能处理的事项（例如重启后已失效的审批）不显示成"待处理"；系统不确定的事项明确标出"不确定"。

### P3 在原地处理

只能跳转的条目就是一条链接。v1 的目标是：硬阻塞类义务（审批、提问、计划审批）大多数情况下不用离开收件箱就能处理；其余类型一键跳到准确位置，比如具体的那张提问卡片或者那一轮对话。

### P4 默认安静

- 没有义务时，页面只显示一行"没有需要你的事"，以及当天挡掉了多少条。
- 不弹窗，不发系统通知（投递通道交给后续插件，见 [004](004-extension-api.md)）。
- 瞬时错误、可以自动恢复的失败、进度消息一律不进收件箱。

### P5 单一事实来源，随时可以重建

收件箱是**投影**：从 Session 日志和现有 Host 状态推导出来，任何时候都能从头重建。插件自己只存三样事实来源里没有的东西：人的处置、外部插件提交的义务、账本。删掉插件的数据，不影响任何 Session。

### P6 上手成本趋近于零

- 装上就生效：没有必填配置，不需要 `stateDir`（原型需要），没有初始化步骤。
- **不新增模型可见的工具和 prompt**：不增加 token，不影响 KV cache，不改变 agent 行为。
- 装上之后立即对已有 Session 生效，最近的历史义务也会回填。
- 卸载之后不留痕迹：不写 Session 事件，不改 preset。
- 中英文双语，跟随 DSH 的语言设置。
- 能改变 agent 行为的选项（例如异步提问）一律默认关闭，开启需要一次明确确认，并在开启时说清楚后果。

### P7 先有扩展点，再有功能

内置的义务来源（审批、提问、goal……）通过和第三方**完全相同**的公开 API 接入，不走内部捷径。这样后续的 work item、GitHub、飞书插件接进来时，用的是一套已经被验证过的接口，而不是临时补出来的。

## v1 不做什么

- 不做团队共享、指派、多用户（D1）。
- 不发推送：系统通知、IM、邮件都交给 Channel 插件。
- 不接外部 Source：GitHub、飞书交给 Source 插件。
- 不让模型给义务打分排序：排序规则是确定性的（见 [001](001-domain.md)）。
- 不自动生成权限规则：只**提议**，由人确认（v1.x，见 [006](006-roadmap.md)）。
- 不新增模型工具（D4）。

## 怎么判断它不是玩具

用 [006](006-roadmap.md) 里的度量判断，下面三条在自己用一周后都要成立：

1. 为了找"谁在等我"而去翻 Session 列表的次数接近 0。
2. 硬阻塞义务从出现到被处理的中位时长明显下降。
3. 噪音率（没做任何动作就被忽略的义务占比）低于 20%。超过的话，回头改义务来源的规则，而不是在收件箱里加过滤器。

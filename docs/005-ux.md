# 005 交互设计

收件箱页面只回答一个问题：**现在有什么需要我？** 原型面板的另外两个问题（系统是否健康、某件工作的完整历史）不在这里回答，前者留给后续的 work-item 插件，后者就是 Session 本身。

页面遵循原型 [005 Panel](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/005-panel.md) 的原则：只放重要的东西、定义明确、计数诚实、默认安静、使用 DSH 的设计 token。

## 入口

- 侧栏 `sidebar.panellist` 里放一个图标。
- 徽标显示 `system` + `hard` 类型的打开义务数，为 0 时不显示；有 `system` 义务时徽标用警示色。
- 不弹窗，不发系统通知，不加 toast。

### 分组

| 分组 | 内容 | 出现条件 |
|---|---|---|
| 系统 | `system` | 有条目时才显示 |
| Agent 在等你 | `hard`：审批、计划、提问 | 有条目时才显示 |
| 待你决定下一步 | `soft`：goal 受阻、轮次失败、待验收 | 有条目时才显示 |

分组之间、组内条目的顺序见 [001](001-domain.md) 的"排序"一节。分组标题上的数字就是这个分组的条目数。

### 条目的组成

1. **第一行**：类型标签，加上一句话说明在等你做什么（`title`）。标签说的是"它需要什么"，不是内部状态码（原型面板原则 2）。
2. **第二行**：主体（Workspace › Session 标题）· 等了多久 · 截止时间（如果有）。`certainty: 'inferred'` 的条目在这里加一个小的"推断"标记，悬停时解释推断依据。
3. **动作**：最多两个主动作直接显示，其余放在"更多"里。推荐选项排在最前，和 `ask_user_question` 的约定一致。
4. **详情**（`detail`）默认折叠，点击条目展开。

### 动作的反馈

- 点击后，条目进入"处理中"状态，按钮禁用。
- 事实发生变化后，条目淡出；页面顶部出现 3 秒"已处理 · 撤销不可用"的轻提示（审批类动作在 DSH 里本来就不能撤销，这里如实告诉用户）。
- 5 秒内事实没有变化：显示错误原因，并提供"打开 Session"。

### 键盘

| 键 | 作用 |
|---|---|
| `j` / `k` | 下一条 / 上一条 |
| `Enter` | 执行推荐动作（审批类：允许一次） |
| `Esc` | 审批类：拒绝 |
| `o` | 打开主体 |
| `s` | 稍后提醒（默认 1 小时） |
| `x` | 忽略（硬阻塞类型需要二次确认） |

`Enter` 和 `Esc` 的语义和原生审批面板一致（`dsh-client-ui-approval`），用户不需要学两套按键。

## 空状态

```
没有需要你的事。
今天替你挡掉 47 条：自动恢复的错误 12 · 进度消息 31 · 你自己停止的轮次 4
```

整个页面只有这两行，不放引导、插图或功能介绍。第一次打开时在第二行下面多显示一句"它会自动收集所有 Session 里等你处理的事，不需要任何设置"，之后不再出现。

## 稍后提醒与静音

- **稍后提醒**：1 小时、今晚、明早、自定义时间。到期时条目回到原位置，等待时长按最初出现的时间计算。
- **静音**：只针对 `soft` 类型，范围可以是"这个 Session"或"这个 Workspace"，例如"这个 Workspace 的待验收不用提醒"。`hard` 和 `system` 不能静音，因为 agent 真的停下来了，静音只会让它一直等下去。
- 静音规则集中显示在设置页里，可以随时撤销。

## 设置页（在页面右上角，同时挂到 `settings.section`）

v1 只有这几项，**全部有默认值**，不改也能正常使用：

| 设置 | 默认 | 说明 |
|---|---|---|
| 静音规则 | 无 | 只能在条目上添加，在这里查看和撤销 |
| 待验收（`review`）类型 | 开 | 觉得吵可以整体关掉 |
| 账本保留天数 | 90 | |
| 异步提问（v1.1） | 关 | 开启后 `ask_user_question` 超时会释放 agent 去做别的，你之后在收件箱里回答。开启前会说明这会改变 agent 的行为 |

# 010 项目时间线

> 状态：v1 已实现（2026-11-25），未发布。代码：Host [lib/projects.js](../lib/projects.js)，Client [client.js](../client.js) 中「project timeline (docs/010)」一节，测试 [tests/projects.test.mjs](../tests/projects.test.mjs)。

## 要解决的问题

一个项目（DSH 的 Workspace）用久了，下面会积累几十个会话。每个会话只有一个标题，想知道「这个项目这两周到底做了什么、改了哪些文件、哪件事卡在哪」，只能一个个点开翻。

项目时间线把一个项目下所有会话的记录读一遍，整理成两种视图：

- **时间线**：按天分组，最新的在上面。每一条是某个会话的一轮：几点、哪个会话、你问了什么、Agent 最后的结论、这一轮改了哪些文件、跑了几条命令、结果是完成、出错还是中止。同一会话连续的几轮只在第一条显示会话名。
- **会话**：每个会话一行：标题、轮数、改动文件数、最近活动时间，下面是「起因」（第一轮你问的）和「最近结论」。展开后是逐轮的问与答，以及改过的文件（带次数）、运行过的命令、最后一份待办清单。

页头显示项目名、路径、最近活动时间，以及会话数、轮数、改动文件数、有活动的天数。右侧栏列出正在进行的会话和改动最多的文件。

## 只读，不打扰

这是硬约束：

- 只用 `sessionQuery.listSessions` 和 `sessionQuery.readSession`。后者读出完整日志，**不会让会话变成 live**，不会唤醒 Agent。测试里用一个代理对象包住 sessionQuery，调用任何其他方法都会抛错。
- 不创建会话，不发 prompt，不调用模型，不写任何存储。点会话名或「打开 ↗」只是跳转到那个会话。
- 侧栏入口注册时不读任何东西。只有打开这个页面时才开始读，离开页面后不再因为会话变化而重读。
- 需要迁移格式的旧会话（`formatStatus: 'migration-required'`）不读，以免触发迁移；页面右侧栏注明跳过了几个。
- 子代理会话不单独列出，只在父会话上显示「N 个子代理」。
- 只读所选项目自己的会话（`workspace.sessionIds`）。详情接口会拒绝不属于该项目的会话 id。

## 从日志里取什么

全部是确定性的提取，不猜测：

| 字段 | 来源 |
|---|---|
| 问 | 这一轮第一条 `user/message`，且 `source.kind === 'user'`。注入的上下文、工具结果都不算 |
| 结论 | 这一轮最后一条带文字的 `assistant/message`。去掉代码块、推理和 Markdown 标记，保留标识符里的下划线；最多 480 字 |
| 结果 | `turn/end` 的 `reason.kind`：完成 / 出错（附错误信息）/ 中止 / 被打断 / 输出被截断；没有 `turn/end` 就是进行中 |
| 改过的文件 | `edit`、`write` 的 `file_path`，`apply_patch` 里的 `*** Add/Update/Delete File:` 和 `*** Move to:`；项目路径下的显示为相对路径。`read` 等只读工具不算 |
| 命令 | `bash` 的 `command`，每轮保留前 6 条，计总数 |
| 待办 | 最后一次 `todo/write` |
| 标题 | 最后一次 `session/title`；没有时用第一轮的问 |

## 性能

- 每个会话的摘要按浏览器看到的 `updatedAt` 缓存在 Host 内存里（最多 600 个）。没变的会话不会再读。
- 一次请求最多新读 6 个会话，按最近更新排序；页面在还有未读会话时继续请求，页头显示「正在读取会话，还剩 N 个」。
- 时间线一次最多返回 240 轮，单个会话详情最多 200 轮；更早的轮次会注明没有列出。
- 页面打开期间，所选项目下的会话有变化（更新时间、运行状态）时，2.5 秒后重新读取变化的那几个。

## 没做的（有意留到后面）

- **模型生成的总结**：Host 上有 `ctx.llm` 可以不建会话直接调用模型，能写出更像人话的「这个项目这周做了什么」。但它消耗 token、需要配置 API key，也可能出错，所以 v1 不用。以后可以做成手动按钮，并且明确显示花费。
- 跳到会话里的某一轮：目前只能打开整个会话。
- 摘要持久化：Host 重启后要重新读；靠逐步加载来控制成本。
